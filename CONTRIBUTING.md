# Contributing to Spool

Thanks for helping with Spool. This library is **experimental `1.0.x`**
(Apache-2.0). The public API may change while that status remains — please call
that out in issues and PRs when behaviour or headers move.

Public docs live at [spool.relicloops.org](https://spool.relicloops.org). The
README, `docs/`, and the public header in this repository remain the source of
truth when they disagree with the site.

By participating, you agree to the [Code of Conduct](CODE_OF_CONDUCT.md).

## Prerequisites

| Tool | Role |
|------|------|
| **GCC** 14+ or **Clang** 18+ | C23 dialect (`c_std=c23`); selected by Meson and shared with Ceedling |
| **Meson** (≥ 1.4) + **Ninja** | Library |
| **Ruby** + **Ceedling** `1.1.1` | Unit tests (Unity; **no CMock** — `use_mocks: false`) |
| **gcovr** | HTML coverage generated by the Meson test target |

```bash
meson --version
gem list ceedling
gcovr --version
```

## Build and test

The `tests` feature is disabled by default, so standalone and subproject builds
produce only `libspool` and `spool_dep` without requiring Ruby or Ceedling.

```bash
meson setup build -Dtests=enabled
meson compile -C build
meson test -C build --print-errorlogs
```

Meson:

1. Selects the C compiler (and matching gcov/gcovr tools).
2. Fetches Valve from `subprojects/valve.wrap` when no local override exists.
3. Writes `build/ceedling-toolchain.yml` and the `build/spool-ceedling` wrapper.

After configure, use the wrapper for direct Ceedling sessions:

```bash
build/spool-ceedling test:all
build/spool-ceedling gcov:all
```

Coverage HTML lands at `.cache/ceedling/artifacts/gcov/gcovr/spool-coverage.html`.

Local Valve co-dev (gitignored):

```bash
ln -sfn ../valve subprojects/valve
```

## Versioning

Spool uses `MAJOR.MINOR.PATCH-BUILD` (tags: `vMAJOR.MINOR.PATCH-BUILD`), for
example `1.0.0-000` / `v1.0.0-000`. While experimental, a MINOR bump may break
the public contract — pin exact tags in consumer wraps.

## CI

GitHub Actions runs the Meson-to-Ceedling workflow with GCC and Clang on
**Ubuntu** plus Clang on **macOS**. Every runner requires the tests and gcovr
HTML report to succeed, then uploads its report as a workflow artifact. The
workflow runs on version tags matching `v[0-9]+.[0-9]+.[0-9]+-[0-9]+` (for
example, `v1.0.0-000`; bare `v1.0.0` is not a release tag) and through manual
`workflow_dispatch`; see [the CI workflow](.github/workflows/ci.yml).

## Pull requests

- Prefer Ceedling tests for new public helpers.
- Keep Spool a Valve companion: do not dump Valve headers into `spool.h`.
- Call out experimental API moves in the PR summary.
